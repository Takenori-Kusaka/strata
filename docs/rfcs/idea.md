## 🗺️ Part 1: Structured Executive Concept (構造化された初期構想案)

### 1. Vision & Origin (発想の原点)
* **Goal:** Create an interactive "Lean Canvas AI Editor" that goes beyond static Markdown rendering.
* **Evolution:** Realized that the underlying patterns—translating inputs to task checklists, tracking manual user operations, attaching rich evidence (video/screenshot), supporting peer reviews, and using generative AI for downstream formatting—are universal across many business tasks (e.g., QA testing, user journey mapping).
* **Mission:** Strata was conceived as a **universal, headless foundation** to build collaborative, human-AI workspace applications.

### 2. Architecture & Layered Design (抽象化とクラス設計)
To ensure maximum customizability, extensibility, and scalability, Strata utilizes a decoupled, abstracted architecture:

* **Database Layer (DB層):**
  * Abstract interface to support both lightweight local-first database engines like **PGLite** (for in-browser/Docker offline execution) and enterprise-grade serverless databases like **Amazon DSQL**, Aurora, or DynamoDB (Single-Table design).
* **AI Orchestration Layer (AIリクエスト層):**
  * Abstracted repository interface decoupling the application logic from the AI provider. Managed via environment variables to toggle between direct model calls, custom serverless runners, or Amazon Bedrock Agents.
* **Storage & Project Isolation (ユーザー空間・プロジェクト分離):**
  * Clear hierarchy on storage (S3 path structure): `UserID / ProjectID / Files / Sessions (Threads)`.
  * Facilitates secure dynamic mounting of project directories in ephemeral execution runners.

### 3. Serverless Runtime & Cost Management (極限の低コスト運用)
* **Zero Idling Cost:** Designed to cost nothing when not in use.
* **Ephemeral Micro-VMs:** Spins up isolated, lightweight micro-VM environments (such as AWS Lambda runners) on-demand. When launched, the environment securely mounts the user's workspace directory from S3, builds/reconstruction of the knowledge base, processes the task, and shuts down immediately.

### 4. Interactive Workspace & Action Tracing (作業プロセスと証跡管理)
* **Evidence Tracing:** Captures manual workflow execution details (e.g., screenshots, video recordings, or console outputs during web execution) to establish verifiable, objective evidence.
* **Git-like Task Review:** Every task has a defined pull-request-style "Review" cycle. final deliverables require multi-peer/AI validation.
* **Collaboration Threading (Buzz):** Thread-based workspace chat inspired by Blocks/Buzz where human workers, reviewers, and AI agents communicate seamlessly via mentions (`@agent`, `@user`).
